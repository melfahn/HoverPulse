# NaturalPoint parity for HoverPulse

**[DRAFT] Implementation specification · 21 November 2026.** Ship HoverPulse as a hands-free replacement for NaturalPoint Dwell Clicker 3.3.0039.0. A user must be able to start, select an action, click, drag, pause, resume, configure and quit using the pointer alone. Scope covers the Dwell Clicker executable, its toolbar, settings and supported integration behaviors. SmartNav camera tracking is a separate product function. This specification takes precedence over conflicting detector and toolbar proposals in requirements.md.

## Engineering baseline

HoverPulse main at `2e760805be181148eb2a8b55151511e98ae76f77` passes 7/7 Release tests. Program.cs runs a 50 ms timer and also accepts movement-hook callbacks. DwellDetector.cs measures elapsed wall time inside a circle around the starting point and skips all paused ticks. ToolbarWindow.cs offers five controls selected by button-down. ClickSimulator.cs batches SendInput events and ignores short writes. SettingsService.cs writes directly to the destination and omits default-valued properties. For example, saving audio off can reload as on because its initializer is true. Existing tests use sleeps and exercise the detector only.

The reference is the verified x86 executable, SHA-256 `CB8D235299FFAB67C950DC6D96B00CBD269C0691B43CADE368C7735F5B95CA15`. Its copied code establishes timing and dispatch. NaturalPoint’s manual supplies user-facing selection and lock behavior. Where the manual and binary differ, use the identified build. [NaturalPoint manual, section 4.3](https://portale.siva.it/files/doc/product/au15376_1_smartNAV-manual.html) · [HoverPulse baseline](https://github.com/melfahn/HoverPulse/tree/2e760805be181148eb2a8b55151511e98ae76f77)

## Capability contract and implementation order

| Deliverable | Change in HoverPulse | Acceptance evidence |
|---|---|---|
| 1. Sampled dwell and rearm | In Program and DwellDetector, process one screen-coordinate sample per delivered 100 ms timer tick. Compare with the previous processed sample. Both absolute axis changes must be strictly below MoveLimit. Increment the count on success, otherwise zero it. Fire when count exceeds ClickTime. For ordinary dispatch, set the repeat latch and finish with count = −ClickTime. While latched, a subthreshold step zeros the counter before its normal increment. An active step reaching MoveLimit on either axis clears the latch. Hook events and delayed timers must never manufacture extra samples. | Replay the attached vectors against the production detector with an injected sample and action recorder. Test both axes and signs, diagonal drift, 60 seconds motionless, and timing limits 1 and 50. One long delivery delay produces one tick. |
| 2. Toolbar and hands-free resume | Program resolves the hit target before dispatch. A toolbar dwell activates its control internally. Implement left, right, double, two-stage drag, temporary override, locked default, pause/resume, options, move and quit. Use familiar order and state cues with original HoverPulse artwork. Dwelling on a mode selects one use. Moving away and selecting it again locks it. Completing a temporary action restores the locked mode. Keep the pause control reachable in the collapsed toolbar. | Run each mode as temporary and locked, including two full drag cycles; selecting a control produces zero desktop clicks. Verify every operation pointer-only. Confirm mode, position, size and feedback at each transition against the reference. |
| 3. Pause and dispatch | Paused samples outside the toggle preserve the last point and counter. Inside it, the latched rearm threshold is 2 pixels per axis; ordinary dwell counting still uses MoveLimit. A dwell toggle flips active state, clears the count inside the handler and finishes at −ClickTime. It preserves an active drag. In ClickSimulator implement the saved legacy mouse_event path and the alternate SendInput path. Preserve left/right down-up ordering, double pairs, drag down then later up. The binary pumps pending messages between legacy click events and spaces the alternate click edges with 100 ms sleeps. Preserve observable order and pacing without duplicate dispatch during reentry. | Record timestamped button edges in a disposable Windows receiver, for each action on both backends. Pause during held drag must emit no up. Resume and drop must emit exactly one up. Compare target window, event order, coordinates and inter-edge timing with separate reference runs. |
| 4. Settings, startup and integration | Implement a dwell-operable options dialog, OK/cancel, sound, three sizes, three float modes, toolbar position, locked default and click backend. Use profile import or explicit profile selection and store subsequent changes in HoverPulse settings. Verify cancel, restart and interrupted writes. Compare all three size/float modes and toolbar moving on mixed-DPI monitors. Trace the observed companion registration and explicit enable/pause/control messages and verify required interactions with a test double. |
| 5. Hardening and release | Own the timer and button state per interactive session. Serialize dispatch. Detect startup, timer and cursor-read failures. After desktop loss discard stale progress and reacquire a fresh sample. Track owned button-downs, handle known partial delivery without replaying a click, and distinguish planned pause from orderly exit. Keep a reachable recovery control. Use atomic settings replacement and a last-good copy. | Exercise short/zero dispatch, failed cursor reads, reentrant callbacks, second instance, exit during drag, forced termination, sleep/wake, lock/unlock, RDP reconnect, monitor removal, and restricted/elevated targets. Verify recovery and record Windows limits. A process kill cannot run cleanup; test actual resulting button state. |

**Timing range correction.** The installed English dialog prints 0.1 and 2 seconds. Its initialization at 01002552–01002591 sets the time trackbar to **1–50** and the movement trackbar to **2–20**. Copied MFC42 ordinal 6111 sends trackbar range-min and range-max messages. Use the selectable range. For the user’s setting of 2, the third qualifying sample after a reset dispatches. Keep the displayed setting distinct from a guarantee of elapsed milliseconds.

### Coordinate units at different display scales

The signed reference is DPI-unaware. At 150% Windows scaling a 6-physical-pixel step measured 4 reference units. A 7-pixel step measured 4 or 5 units depending on its starting coordinate. Across 30 horizontal and vertical trials, exactly the steps reaching 5 reference units rearmed ordinary dwell. The detector reads Windows' DPI-unaware cursor coordinates for this comparison. The toolbar uses the physical position for target hit testing, drag placement and monitor-aware paint. The paused toggle uses the same reference coordinates for its 2-unit rearm threshold.

## Implementation entry point

First replace the time-dependent detector tests with a deterministic compatibility suite alongside any tests still relevant to other behavior. Pass a sampled point and hit target to a pure state transition; return an action for Program to route to either the toolbar or a recording/native backend. Keep locked mode, one-use selection, held drag, pause, repeat latch, count and previous sample explicit. Reuse the existing Win32 message loop, toolbar renderer and settings service. Use widened signed arithmetic for screen-coordinate deltas. Keep optional overlays and hotkeys independent of the core state and disabled in the reference profile unless the reference calls for them.

The companion fixtures give initial state, absolute screen coordinates and expected actions by one-based delivered tick. A normal desktop action is recorded as one logical click before expansion into native edges. A toolbar toggle records an internal action only. These fixtures establish engine behavior; Windows integration also needs the independent receiver.

## Release decision

“100%” means every reference capability above has a named passing case, including the remaining integration and UI characterization. Compare reference and candidate separately on a disposable Windows desktop using the same scripted motions. Record the executable hashes, profile, Windows build, DPI, delivered samples, target and resulting actions. For timer jitter, establish the reference distribution on the same host before judging the candidate; require exact logical event counts and ordering. Run deterministic coverage on every build, a full Windows matrix for advertised platforms, and an eight-hour candidate soak with repeated click, drag, pause and resume cycles. The eight-hour soak is a proposed engineering threshold. Require zero unintended clicks, missed expected actions, stuck owned buttons under supported conditions, or loss of hands-free resume. Record all failures and rerun the affected matrix after repair.

Before declaring full coverage, characterize the reference’s first sample after launch, first-run layout with the registry fallbacks, mode changes mid-drag, modal options behavior, float/position persistence, companion availability, and failure or exit with a held button. Link each result to a test or an explicitly documented platform limit. A blocked SendInput call can report zero without identifying UIPI as the cause; legacy mouse_event has no delivery count. Use receiver-side observations for both. Release and rollback rehearsals belong on an isolated machine. Any production trial or cutover is a separate decision.
